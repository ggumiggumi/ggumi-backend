## Git 브랜치 전략
### 1) Github-Flow
### develop → feat/이슈번호, fix/이슈번호, refactor/이슈번호
1. 각 팀원은 로컬 feat/이슈번호 에서 각자 작업
2. 작업 완료 후, 원격 develop 브랜치에 풀 리퀘스트(PR) 샹송
3. 코드 리뷰 후, 리뷰어에 승인(Approve)받고 병합(Merge)
4. 모든 팀원은 develop 브랜치에 변경 사항이 병합될 때마다 pull 받아 최신 상태 유지

### 2) Git Convention
| 커밋 타입  | 설명                                |
|-------------|-------------------------------------|
| feat        | 새로운 기능에 대한 커밋            |
| fix         | 빌드 관련 파일 수정에 대한 커밋    |
| build       | 빌드 관련 파일 수정에 대한 커밋    |
| chore       | 그 외 자잘한 수정에 대한 커밋      |
| ci          | CI 관련 설정 수정에 대한 커밋      |
| docs        | 문서 수정에 대한 커밋              |
| style       | 코드 스타일 혹은 포맷 등에 관한 커밋 |
| refactor    | 코드 리팩토링에 대한 커밋          |
| test        | 테스트 코드 수정에 대한 커밋       |
